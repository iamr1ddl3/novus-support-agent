IN THIS LESSON

A customer sends a question to POST /query:

What is the foreclosure penalty for an Elite customer?

run_agent() opens a Langfuse root span, support-agent, then runs two safety checks before the LangGraph state machine sees anything.

✦
KEY IDEASome bank questions need an answer, some need a tool, and some need a human. The agent's whole job is telling these apart, and showing its working.

The input guardrail blocks off-topic questions (IPL scores), prompt injection, staff impersonation and requests for internal policy, before any tool runs.

This question is on-topic, so it passes.

!
KNOWN ISSUEIt over-blocks some valid messages today, including the UI's own "Escalation" and "Fraud" example chips and any message with a phone number or PAN.

The PII anonymizer swaps personal data for typed placeholders. The tools, the LLM and the Langfuse trace all see only the clean text:

My account 50100234567 shows a wrong penalty
→ My account <IN_BANK_ACCOUNT> shows a wrong penalty

Placeholders are put back only in the final answer. This question has no PII, so it goes through unchanged.

classify: gpt-4o-mini (temperature 0) labels the intent, then a lookup table picks the tool.

order_statusorder_tracker
product_info · billing · generalpolicy_kb
membershipaccount_lookup
return_or_refund2nd LLM call: policy_kb or multi_tool

This question is return_or_refund. It's about one customer's tier, so the disambiguator picks multi_tool.

tool, pass 1: policy_kb. The agent keeps no copy of the bank's policies. It calls the Novus RAG Assistant's /query API in Hybrid mode and uses the passages it returns.

If the RAG API is unreachable, a small in-memory retriever takes over, so the agent still answers.

✦
DESIGN DECISION ADR-8One source of truth for policy. That's why the RAG app is deployed first and torn down last.

evaluate decides the next step, in this order:

1steps ≥ 6 → respond
2multi_tool with only 1 result → back to tool
3escalation check → escalate
4otherwise → respond

Rule 2 fires: loop back. Pass 2 runs account_lookup for Elite tier details (a mock of the core banking system).

✦
KEY IDEAMAX_STEPS = 6 means the graph can never loop forever.

evaluate runs again: two results, no escalation keyword, so respond.

respond answers only from the tool results: the foreclosure rules plus the Elite tier details. If the answer weren't there it would say so and point to support, instead of guessing. Then PII is restored for the customer.

A different customer: I have complained three times and nothing happened. I want to escalate to a manager.

classify → general → policy_kb (grievance passages). In evaluate, stage 1, a free keyword scan over 37 phrases, matches escalate. Only then does stage 2 ask gpt-4o-mini to confirm. It does, so escalate writes an empathetic handoff and sets escalation = true.

✦
FAILS SAFEIf the stage-2 call fails, the agent trusts the keyword hit and escalates. Stage 2 exists to cut false alarms like "Is UPI urgent transfer free?".

The input guardrail flags it as off-topic. It's blocked before the graph: no tool, no answer call. The customer gets a polite refusal, intent = "blocked", and the trace is tagged blocked.

A 42-query golden set: 32 answerable plus 10 that should escalate. CI fails a PR if any metric drops more than 5 points.

WHY ROUTING BEATS INTENTSeveral intents map to the same tool, so a wrong label often still picks the right tool. LLM-judge noise is real too: one PR failed with no code change and passed on re-run.

One query, three possible endings:

  • Respond, grounded only in tool results, with PII restored.
  • Escalate, after a free keyword scan and an LLM confirmation, failing safe.
  • Blocked by the guardrail before the graph runs.

It runs on ECS Fargate Spot behind an ALB, about $1.50 a day, and reaches policy data through the RAG assistant.
